Performance & The Big "O" Notation
----------------------------------
- When faced w/ multiple solutions for a given problem
    - To determine the best one 
        - Figure out each solution's run-time performance
        - Pick the solution that takes less amount of time to execute

    - Using a stopwatch is NOT a good idea due to its dependence on
        - The PC hardware the test is running on
        - The background processes running concurrently

    - It is best to test a solution's performance in a generalized form
        - NOT based on time units as it varies
        - In a mathematical form referred as Time Complexity


- Time Complexity
    - It is a chart that w/ two (2) axis where:
        - x-axis = Time
        - y-axis = Items (input size fed to the algorithm)

    - The chart is referred as the Big "O" Notation
        - Mathematically expressed as "O(n)"
            - Where "n" refers to the number of affected items 


- On the practice code
    - Focusing on the function "getMin()"
        - Determine the Time Complexity of the algorithm used in the function


    - Group parts of the code into two (2) categorizes
        - Constant  = parts of the code that runs ONCE
        - Dynamic   = parts of the code that runs MORE THAN ONCE

        - To serve as a visual aid
            - Discern parts of the code that fits in the given category
                - Manually insert breakpoints using "console.log()"
            
            - Load the web app on the browser
                - Launch the browser's JavaScript console
                - Visually count the number of times a part of the code executes

        
    - Focus ONLY on parts of the code that are dynamic
        - As it is heavily dependent on the input size fed to the algorithm
            - Influences the number of times that part of the code executes (operates)
                - Based on the given input size
            
            - If the function "getMin()" is passed w/ an array of 100 elements
                - The "for" loop will execute 99 times based on how it is configured

        - Based on the behavior of the implemented algorithm in the function
            - It's performance is dependent on the input size

            - The bigger the size, the longer it takes to execute
                - It grows in a linear way
                - But does NOT grow exponentially (or slower)

        - The algorithm has a "Linear Time Complexity"
            - Mathematically expressed as "O(n)"
